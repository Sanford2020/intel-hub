# Review Checklist

这份清单用于合并前审查。审查者优先查找会影响交付、协作、数据安全和用户体验的问题。

## 1. 范围与协作

- [ ] 本次变更符合任务卡或交接说明。
- [ ] 没有修改其他 agent 明确负责的文件。
- [ ] 没有删除或重写他人已有内容，除非交接中明确授权。
- [ ] 新增文件位置符合 `standards/PROJECT_STRUCTURE.md`。
- [ ] 仍然存在争议的需求、接口或文件边界已经记录。

## 2. 功能正确性

- [ ] 核心用户路径可以按预期完成。
- [ ] 错误状态有合理处理，不会静默失败。
- [ ] 空数据、重复数据、超长输入、权限不足等边界条件已经考虑。
- [ ] 前后端字段、API、状态码和错误格式一致。
- [ ] 异步任务、重试、轮询或缓存不会导致重复提交或脏数据。

## 3. 代码质量

- [ ] 代码保持简单，未引入不必要抽象。
- [ ] 命名能表达业务含义。
- [ ] 重复逻辑在合理范围内；共享逻辑有清楚归属。
- [ ] 日志和错误信息对排查有帮助，但不泄露敏感数据。
- [ ] 没有临时注释、死代码、无用文件或调试输出。

## 4. 测试与验证

- [ ] 与变更相关的测试已新增或更新。
- [ ] 已执行最小必要验证命令。
- [ ] 验证覆盖成功路径和至少一个关键失败路径。
- [ ] 如果不能运行测试，原因和补救方式已经写入交接。
- [ ] 手动验证步骤足够具体，其他 agent 可以复现。

## 5. 安全与隐私

- [ ] 没有提交真实密钥、令牌、私钥、密码或会话 cookie。
- [ ] `.env.example` 只包含占位值。
- [ ] 用户输入经过校验、转义或参数化处理。
- [ ] 权限检查在可信边界执行，不只依赖前端隐藏。
- [ ] 日志、错误、导出文件不包含敏感个人信息。

## 6. 前端体验

- [ ] 页面在目标桌面和移动视口中无明显重叠、溢出或遮挡。
- [ ] 加载、空状态、错误状态和成功状态都有明确表现。
- [ ] 表单控件有标签、校验和可恢复错误提示。
- [ ] 交互元素可通过键盘或辅助技术理解。
- [ ] 视觉风格与项目已有设计一致。

## 7. 后端与数据

- [ ] 数据模型和迁移脚本与代码一致。
- [ ] 数据库查询不会明显造成 N+1、全表扫描或无限分页。
- [ ] 外部服务失败时有超时、降级或明确错误。
- [ ] 后台任务具备幂等性或重复执行保护。
- [ ] API 文档或示例请求已同步更新。

## 8. 发布准备

- [ ] README 或运行文档包含启动、测试、构建和部署方式。
- [ ] 新增环境变量、依赖和端口已记录。
- [ ] 构建产物、缓存目录、日志文件未被误提交。
- [ ] 回滚方式或风险点已经说明。
- [ ] `scripts/validate_project.ps1` 的输出没有未处理的 error。
