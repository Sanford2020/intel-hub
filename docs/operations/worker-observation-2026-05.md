## Top Failure Reasons (RSS ingest)

1. **HTTP 404 Not Found** — dead or moved feed URLs (Reuters-style paths, Oryx blog feed)
2. **HTTP 403 Forbidden** — upstream blocks automated fetch (Understanding War, others)
3. **SSL UNEXPECTED_EOF_WHILE_READING** — transient TLS / proxy issues
4. **Invalid XML / parse errors** — malformed or HTML error pages returned as RSS
5. **Timeout / connection reset** — slow or unreachable hosts under batch dispatch

These are source-quality / network issues, not worker crashes. OPS-01 seed hygiene reduces known-bad feeds but DB still contains failing due sources.

## Risks

- **Not a full 24h window on this host** — extended ~39 min run proves loop integrity; unattended 24h must use `ops-worker-observe.ps1 -DurationHours 24` on Linux with sleep disabled.
- **Windows solo worker** — queue backlog under full RSS dispatch; use prefork + multiple workers or rate-limit due sources in production.
- **AI mock mode** — reports are mock summaries; acceptable for ops loop validation, not content QA.
- **Celery inspect** — still unreliable on local Windows; use logs + CSV sampling instead.
- **M6 auth** — stats/ingest scripts must login (`SMOKE_EMAIL` / `SMOKE_PASSWORD`).

## Conclusion

The **ingest → analyze → alert** loop ran continuously without manual intervention during the extended supervised window: Beat fired on schedule, articles and reports increased, **804 new alert events** were recorded, and the worker recovered from per-source RSS failures without crashing.

**Verdict: APPROVE with risk** for commercial daily operations when deployed with:

1. Dedicated worker host (Linux preferred), sleep disabled
2. Queue depth monitoring (`default` queue alert if > N for > 30 min)
3. Optional second worker or throttled RSS dispatch for large source fleets
