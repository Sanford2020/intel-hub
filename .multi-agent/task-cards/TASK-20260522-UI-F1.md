## Goal

把前端从"功能堆叠型后台"推进到"专业情报工作台"的基础形态：

- 统一导航与移动端入口。
- 抽取基础 UI 组件，减少页面内联样式。
- 将 `/` 首页改造成 Dashboard：今日指标、Top 情报、系统状态、告警/趋势 fallback。
- 保持现有 API 和业务逻辑不变。

## Implementation Requirements

- `/` 首屏必须从产品介绍变成工作台：指标、Top 情报、系统状态、行动入口。
- 移动端必须能访问所有核心页面。
- 新组件需保持小而稳定，不做大规模 UI framework。
- 优先复用现有 `getOverviewStats()`、`getDailyBriefing()`、`apiClient.get('/api/v1/health')`。
- API 缺数据时显示空状态，不新增后端接口。
- UI 文案统一中文，英文仅保留技术名词或品牌名。
- 深色模式必须可读，避免硬编码 `bg-white` 而无 dark class。

## Acceptance Criteria

- 首页第一屏能看到今日工作台，而不是功能营销卡片。
- 桌面导航按情报/分析/运营语义组织，移动端有菜单入口。
- 至少 6 个基础组件被页面实际使用。
- `gray-*` 新增使用受控，优先使用 `slate-*`。
- Backend offline / briefing empty / stats missing 均不导致首页破版。
