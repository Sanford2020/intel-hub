## Implementation Requirements

### `/briefing`

- 使用 `PageHeader` + `SegmentedControl`。
- 总览使用 `SurfaceCard`。
- 条目使用 `ScoreBadge`、统一标签样式、来源/时间 meta。
- Mock AI 提示使用统一 warning 样式。

### `/articles`

- 筛选区统一为 `SurfaceCard` + `.field`。
- 今日精选是明确的快捷筛选。
- 资讯列表项尽量复用 `ArticleListItem`。
- 分页复用 `Pagination`。
- 保持 `?source_id=` 行为。

### `/articles/[id]`

- 阅读布局保持舒适，不强行拉满屏。
- 来源、发布时间、原文链接、AI 报告使用统一 card/badge。
- 不改变数据获取逻辑。

### `/sources`

- 来源状态、分类、tier 使用统一 badge。
- 采集日志不应使页面严重破版；可保留折叠，不必本卡实现 Drawer。

### `/alerts`

- 规则状态、触发事件、通知方式使用统一 badge。
- 空状态 / 错误状态复用共享组件。

### `/archives` / `/trends`

- 仅当 M5-C 已合流或当前分支已有稳定实现时处理。
- 趋势热力颜色通过统一 token / class，减少 inline color。
- 移动端允许横向滚动，不得破坏页面宽度。

## Acceptance Criteria

- 所有核心页面使用统一 `app-shell` / `PageHeader` / `SurfaceCard` 风格。
- `scoreBadgeClass()`、`formatDateTime()`、`CATEGORY_LABELS` 等重复逻辑显著减少。
- 简报、资讯、来源、告警视觉不再像不同产品。
- 空 / 错 / 加载态一致。
- 移动端 390px 下核心信息可读。
