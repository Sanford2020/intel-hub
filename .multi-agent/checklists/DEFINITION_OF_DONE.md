# Definition of Done

这份 DoD 用来判断一个多 agent 任务、迭代或 MVP 是否真正可交付。每个 agent 完成任务时都应留下可验证证据，而不是只描述“已经完成”。

## 任务级完成标准

- [ ] 任务目标已经实现，且没有扩大到未授权范围。
- [ ] 修改只发生在该 agent 声明的文件或目录边界内。
- [ ] 相关输入、输出、接口、配置或数据结构已经记录清楚。
- [ ] 新增或修改的行为有对应验证方式：自动化测试、手动步骤、截图、日志或命令输出摘要。
- [ ] 已检查错误路径、空数据、权限不足、网络失败、重复提交等关键边界条件。
- [ ] 没有留下临时调试代码、硬编码本地路径、测试账号密码或真实密钥。
- [ ] 如果存在未完成事项，已经记录为明确风险或后续任务。

## 代码完成标准

- [ ] 代码符合项目已有风格、命名和目录结构。
- [ ] 公共接口保持向后兼容；如有破坏性变化，已在交接中说明。
- [ ] 复杂逻辑有必要的注释或文档，不依赖口头解释。
- [ ] 依赖新增、环境变量新增、迁移脚本新增都已在 README、`.env.example` 或相关文档中说明。
- [ ] 自动化检查通过，或失败原因已被定位并记录。
- [ ] 没有引入明显性能退化、无限循环、重复请求或不受控资源占用。

## 文档完成标准

- [ ] README 或入口文档能让新 agent 理解如何启动、测试和验证项目。
- [ ] PRD、任务卡、架构说明、API 文档与实际实现没有明显冲突。
- [ ] 交接文档包含 `Done`、`Changed`、`Verified`、`Risks`、`Next`。
- [ ] 决策变更有记录，尤其是接口、数据模型、认证、部署和安全策略。

## 测试与验证标准

- [ ] 至少执行一次与任务相关的最小验证。
- [ ] 用户主路径已经验证。
- [ ] 失败路径或关键边界条件已经验证。
- [ ] 若测试无法运行，已说明缺少的依赖、命令、服务或权限。
- [ ] 验证结果可以被其他 agent 复现。

## 合并前完成标准

- [ ] 所有 agent 的交接状态一致，没有互相等待的未解决依赖。
- [ ] 文件边界冲突已经解决，没有多人并行覆盖同一文件的风险。
- [ ] `scripts/validate_project.ps1` 已运行，结果已记录。
- [ ] `checklists/REVIEW_CHECKLIST.md` 已完成。
- [ ] `standards/QUALITY_GATES.md` 中对应阶段的门禁已通过或获得明确豁免。

## 可接受的豁免

豁免必须写清楚三件事：

```text
Gate:
Reason:
Owner:
Follow-up:
Expiry:
```

没有 owner、没有后续动作、没有过期时间的豁免，不应视为完成。
