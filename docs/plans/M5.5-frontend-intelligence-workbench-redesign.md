# M5.5 — Frontend Intelligence Workbench Redesign

> **Master:** Cursor · **Builder:** Windsurf · **Validation:** Codex
> 状态：规划完成 · 可按任务卡派单 · 2026-05-22
> 关联：`TASKS.md`、`docs/plans/roadmap-3-employees.md`、`.multi-agent/task-cards/TASK-20260522-UI-*.md`

## 1. 背景与问题

当前 `apps/web` 已覆盖 Dashboard、简报、资讯、来源、告警、归档、趋势等核心流程，但页面气质仍偏"功能堆叠型后台"：

- 首页偏产品介绍，不像分析员每天使用的情报工作台。
- 导航入口平铺，未按"情报 / 分析 / 运营"组织。
- 页面内联 Tailwind 较多，`gray` / `slate`、圆角、按钮、标题样式不一致。
- 移动端导航缺失：`AppNav` 在小屏隐藏导航，没有汉堡菜单或底部导航。
- 组件层较薄：`Button`、`.surface`、`.field` 已存在，但未被稳定复用。
- 简报、资讯、趋势、归档的展示关系不清晰，用户不知道先看哪里。

**目标：** 把前端改造成"专业情报分析工作台"：用户打开后先看到今日重点、告警、趋势异动和系统状态，而不是产品功能介绍。

## 2. 产品与设计原则

### 2.1 产品定位

```text
不是普通 CRUD 后台
而是情报分析员的每日操作台
```

用户一打开就能回答：

1. 今天有什么重要情报？
2. 哪些主题正在升温？
3. 哪些来源贡献有效内容？
4. 哪些告警被触发？
5. 系统采集 / 分析链路是否正常？

### 2.2 视觉原则

| 原则 | 说明 |
| --- | --- |
| 冷静专业 | 以 `slate` 中性色为主，减少装饰性色块 |
| 高信息密度 | 卡片紧凑、表格清晰，优先展示判断所需字段 |
| 数据优先 | 指标、分数、来源、时间、标签比插画更重要 |
| 深色友好 | 暗色模式必须可读，避免硬编码浅色背景 |
| 一致复用 | 所有页面使用相同 shell、header、card、badge、loading/error/empty state |

### 2.3 推荐色彩

| 用途 | Light | Dark |
| --- | --- | --- |
| 页面背景 | `slate-50` | `slate-950` |
| 卡片背景 | `white` | `slate-900` |
| 卡片边框 | `slate-200` | `slate-800` |
| 主操作 | `blue-600` | `blue-400 / blue-500` |
| 成功 | `emerald` | `emerald` |
| 警告 | `amber` | `amber` |
| 风险 | `rose` | `rose` |

避免继续扩大 `gray-*` 与 `slate-*` 混用。新代码优先使用 `slate-*`。

## 3. 信息架构

### 3.1 导航分组

将现有平铺导航：

```text
首页 / 简报 / 归档 / 趋势 / 来源 / 资讯 / 告警
```

重组为：

```text
情报：今日简报 / 资讯库
分析：趋势分析 / 归档
运营：来源运营 / 告警规则
```

### 3.2 推荐顶部导航

桌面端：

```text
Intel Hub | 今日简报 | 资讯库 | 趋势分析 | 归档 | 来源运营 | 告警规则
```

移动端：

- P0：顶部汉堡菜单 + Drawer。
- 可选 P1：底部 4 Tab：`简报`、`资讯`、`趋势`、`更多`。

### 3.3 默认着陆页

`/` 保留，但语义从 Landing Page 改为 **Dashboard / 今日情报工作台**。

│ 今日 Top 情报                 │ 最新告警              │

│ 3. ...                        │                      │
└──────────────────────────────┴──────────────────────┘

### 4.1 Dashboard 数据源优先级

| 区块 | 首选数据 | fallback |
| --- | --- | --- |
| 今日指标 | `/api/v1/stats/overview` + briefing meta | 现有 overview stats |
| 今日 Top 情报 | `/api/v1/briefing/daily` | 空状态引导到 `/sources` / `/articles` |
| 最新告警 | alert events API（若已有） | 告警规则总数 + 引导到 `/alerts` |
| 分类热度 | `/api/v1/archives/trends/category-heat` | 若归档未启用，展示"等待 M5 归档数据" |
| 系统状态 | `/api/v1/health` | offline badge |

若 API 不足，Windsurf 只做前端 fallback，不新增后端接口；后端缺口写到 `REVIEW.md` 或后续 task。

## 6. 页面级规划

### 6.1 `/` Dashboard

**目标：** 今天发生了什么，哪些值得关注，系统是否正常。

必须：

- 移除或下沉"多源采集 / Agent 工作流"等营销式功能卡片。
- 首屏包含 4 个核心指标卡。
- 显示今日简报 Top 5 或空状态。
- 显示系统状态：Backend online/offline、AI 模式、采集/分析调度说明。
- API 失败时保留页面结构，不整块消失。

### 6.2 `/briefing` 今日简报

**目标：** 像日报，而不是普通列表。

必须：

- 使用 `PageHeader` + `SegmentedControl`。
- 总览卡片使用 `SurfaceCard`。
- 简报条目使用统一 `ScoreBadge`、标签样式、来源/时间 meta。
- Mock AI 提示改用 `WarningBanner` 或 `StatusBadge` 组合。

### 6.3 `/articles` 资讯库

**目标：** 专业检索页面。

必须：

- 筛选区改为统一 `SurfaceCard` + `.field`。
- 今日精选作为清晰的快捷筛选。
- 列表项抽成 `ArticleListItem`。
- 分页抽成 `Pagination`。
- 保持 `source_id` query 行为。

### 6.4 `/trends` 趋势分析

**目标：** 看趋势异动。

必须：

- 使用 `PageHeader` + `SegmentedControl`。
- Top 分类卡片统一 `SurfaceCard`。
- 热力矩阵保留，但颜色通过统一 token / class 处理，减少 inline `rgba`。
- 移动端不横向破版；表格可横向滚动。

### 6.5 `/archives` 与 `/archives/[date]`

**目标：** 历史日报库。

必须：

- 列表显示日期、item count、入库数、高相关数、告警数、状态。
- 详情页像可阅读日报：总览、Top 条目、metrics。
- 若 M5-C 尚未完成，M5.5 不直接改这两个页面；等 M5-C 合流后由 UI-F2 统一视觉。

### 6.6 `/sources` 来源运营

**目标：** 来源池运维台。

必须：

- 来源状态、分类、tier 使用统一 badge。
- 采集日志避免长列表撑坏页面；可保留折叠区，后续再做 Drawer。
- 增强异常/失败来源的视觉提示。

### 6.7 `/alerts` 告警规则

**目标：** 规则管理 + 事件监控。

必须：

- 规则状态、触发事件、通知方式使用统一 badge。
- 空状态和错误状态复用 `EmptyState` / `ErrorBanner`。
- 保持现有规则 CRUD 语义，不新增权限逻辑。

## 10. 验收标准

### 老板可见验收

1. 打开首页，第一屏能看到今日指标、Top 情报、告警/系统状态，而不是产品功能介绍。
2. 手机宽度下可以访问所有核心页面。
3. 简报、资讯、来源、告警页面视觉统一，按钮 / 卡片 / badge / loading / error 不割裂。
4. 深色模式可用，有明显切换入口。
5. `npm run type-check && npm run build && npm run test:run` 通过。

### Review 必查

- [ ] 是否引入重型 UI/chart 依赖；默认不允许。
- [ ] 是否改动后端 API；默认不允许。
- [ ] 是否破坏 `source_id`、briefing hours、trends days 等现有交互。
- [ ] 是否有移动端导航。
- [ ] 是否存在中英文混杂的新文案。
- [ ] 是否保留空状态、错误状态、加载状态。
